# 三、API 测试计划

> 项目：学之思在线考试系统 · 测试对象：后台 REST API
> 编制日期：2026-10-06 · 版本：v1.0

---

## 1. 测试目标

1. 验证 8 大业务模块 **40 个接口** 的功能正确性；
2. 验证鉴权/权限模型的安全性（垂直越权、未授权、注入）；
3. 验证异常与边界入参的健壮性（无 500 堆栈）；
4. 建立**可回归、可自动化**的接口测试资产。

## 2. 测试范围

| 范围 | 内容 |
|------|------|
| **纳入** | 认证、学科、题库、试卷/任务、学生答题闭环、消息、用户管理、权限安全 |
| **排除** | 前端 UI 渲染、微信小程序端深度、静态资源 |
| **不测** | 性能压测（仅做单接口响应基线）、兼容性 |

## 3. 测试策略（分层）

```
        ┌─────────────────────────────┐
  L4    │ 端到端测试 E2E（组卷→作答→判分） │  4 条
        ├─────────────────────────────┤
  L3    │ 集成测试（发消息→收消息→已读）   │  1 条
        ├─────────────────────────────┤
  L2    │ 接口功能测试（单接口正/异常/边界）│  ~60 条
        ├─────────────────────────────┤
  L1    │ 冒烟测试（P0 核心链路）         │  29 条
        └─────────────────────────────┘
```

- **自动化优先**：P0/P1 全部自动化，P2/人工型用例保留手工执行。
- **数据驱动**：测试数据与用例分离（`testdata/test_data.json`）。
- **可重复**：用例自带数据准备与清理，可重复执行。

## 7. 准入 / 准出准则

**准入准则**
- 服务可访问（`/api/user/login` 返回 200）
- 测试账号可用、数据库连通
- 接口清单冻结

**准出准则**
- P0 用例通过率 **100%**
- P1 用例通过率 ≥ 95%
- 无未关闭的 **严重/高** 缺陷（或已给出修复方案）
- 自动化套件可一键回归且全绿

## 8. 缺陷分级标准

| 等级 | 定义 | 示例 |
|------|------|------|
| 严重(S1) | 核心功能不可用 / 严重安全漏洞 | 答案泄露、越权改数据 |
| 高(S2) | 主要功能异常 / 数据错误 | 判分错误、无法登录 |
| 中(S3) | 次要功能异常 / 体验问题 | 提示不友好、边界未处理 |
| 低(S4) | 轻微问题 / 建议 | 文案、日志 |

## 9. 风险与应对

| 风险 | 应对 |
|------|------|
| 测试数据污染生产库 | 使用独立 ID 段(9000+) + 用例内清理 |
| 会话/Cookie 失效导致误报 | 会话级夹具 + 失败重试登录 |
| 环境依赖（服务需常驻） | 用例前置校验连接，明确报错 |
