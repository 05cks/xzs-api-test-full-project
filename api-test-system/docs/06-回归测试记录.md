# 六、回归测试记录

> 目的：验证接口在重复执行、修复后重测场景下的**稳定性**与**可重复性**。
> 回归方式：使用同一套 pytest 用例重复执行，比对结果一致性。

---

## 1. 回归策略

| 层次 | 范围 | 触发时机 | 命令 |
|------|------|----------|------|
| 冒烟回归 | P0 核心链路（24 条） | 每次接口变更/构建后 | `python run_tests.py -m p0` |
| 全量回归 | 全部 57 条 | 版本发布前 | `python run_tests.py` |
| 定向回归 | 缺陷相关模块 | 缺陷修复后 | `python run_tests.py -m security -k <kw>` |

## 2. 回归执行记录

| 轮次 | 时间 | 范围 | 用例数 | 通过 | 失败 | xfail | 结果一致性 |
|:---:|------|------|:---:|:---:|:---:|:---:|:---:|
| 第1轮（基线） | 14:36 | 全量 | 57 | 56 | 0 | 1 | — |
| 第2轮 | 14:38 | 全量 | 57 | 56 | 0 | 1 | ✅ 与基线完全一致 |
| 第3轮 | 14:38 | P0 冒烟 | 24 | 24 | 0 | 0 | ✅ 通过 |

> 结果文件：`reports/run_result.json`（基线）、`reports/run_result_round2.json`（第2轮）

## 3. 稳定性分析

| 指标 | 结果 |
|------|------|
| 通过率波动 | 0%（两轮均 56 passed / 1 xfailed） |
| 稳定性 | ✅ 高（用例自带数据清理，无脏数据影响） |
| 执行时长 | 全量 ~1.6s，冒烟 ~0.7s |
| 失败用例 | 无 |

**结论**：自动化套件**可重复、结果稳定**，可作为长期回归资产接入 CI。

## 4. 缺陷回归跟踪

| 缺陷 | 等级 | 关联用例 | 修复后回归范围 | 状态 |
|------|:---:|----------|----------------|:---:|
| DEF-001 答案泄露 | S1 | SEC-007 / E2E-001 / EXAM-003 | `-m security -k answer_leak` + 全量 | 待修复 |
| DEF-002 水平越权 | S2 | SEC-008 / SEC-009 | `-m security -k 越权` | 待修复 |
| DEF-003 分页上限 | S3 | SEC-010 | `-m security -k page` | 待修复 |
| DEF-004 密钥硬编码 | S3 | 代码审查 | 配置检查 | 待修复 |
| DEF-005 CSRF | S3 | SEC-012 | 人工评估 | 待修复 |

**回归验证方法（以 DEF-001 为例）**：
1. 开发修复学生端拉卷接口（剔除 `correct` 字段）；
2. 执行 `python run_tests.py -m security -k answer_leak`；
3. 用例由 `xfail` 变为 `passed`（即不再泄露）后，标记缺陷 Closed；
4. 执行全量回归，确认无回归引入。

## 5. 回归准入/准出

- **准入**：修复版本部署、服务可访问、用例集为最新；
- **准出**：全量回归通过率 100%（P0/P1 全绿）、无新增缺陷。
